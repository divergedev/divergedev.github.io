## The Problem

Your team runs 50 microservices on Kubernetes. A developer changes one service and opens an MR. To test it, you clone the **entire** staging environment — 50 deployments, databases, config maps. It takes 15 minutes and costs $47/day in cloud resources.

**There has to be a better way.**

## The Diverge Way

<CardGrid>
  <Card title="Delta Deployments" icon="rocket">
    Deploy **only the services that changed**. Diverge detects which services are affected by a code change and deploys just those — sharing baseline services for everything else.
  </Card>
  <Card title="Header-Based Routing" icon="random">
    Route traffic to your preview environment with a single HTTP header. No extra load balancers. No DNS wildcard. Works with Istio, Gateway API, and gRPC.
  </Card>
  <Card title="Automatic Lifecycle" icon="setting">
    Environments spin up on MR open and tear down on merge. TTL expiry catches the rest. Zero zombie environments, zero wasted spend.
  </Card>
  <Card title="Database Modes" icon="document">
    Choose how your preview gets data: shared baseline, fresh schema, snapshot clone, or isolated per-schema. Each MR gets the right level of isolation.
  </Card>
  <Card title="Security First" icon="approve-check">
    Finalizer-based teardown, RFC 7230 header validation, path traversal prevention, and constant-time secret comparison ensure your infrastructure stays secure.
  </Card>
</CardGrid>

## How It Works

```yaml
# .diverge.yaml — add to your repo
version: "1"
services:
  api:
    paths: ["services/api/**"]
    image:
      repository: registry.example.com/api
      tag_template: "mr-{{.MR}}"
    helm:
      path: charts/api
  web:
    paths: ["services/web/**"]
    image:
      repository: registry.example.com/web
      tag_template: "mr-{{.MR}}"
    helm:
      path: charts/web

defaults:
  deploy:
    mode: delta
  routing:
    mode: header
    baseline_namespace: staging
  lifecycle:
    ttl: 72h
    cleanup_on_merge: true
```

**That's it.** Open an MR, and Diverge handles the rest.

## Built for Your Stack

- **Kubernetes-native** — CRD-driven, works with any K8s cluster
- **GitOps-first** — Integrates directly with Argo CD Application CRs via Server-Side Apply
- **No-ArgoCD mode** — DirectDeployer with Server-Side Apply, no CD tool required
- **Kustomize + Helm** — ArgoCD Application generation supports both
- **Mesh-agnostic** — Gateway API, Istio, or Linkerd
- **Protocol-aware** — HTTP, gRPC, ConnectRPC with SDK interceptors
- **Git provider flexible** — GitLab and GitHub webhooks
- **Test Integration** — Trigger CI pipelines, poll for results, report in MR comments
- **CLI included** — 7 robust commands (`create`, `list`, `delete`, `open`, `logs`, `validate`, `version`)

## Quality & Features

- Built with **Go 1.26** and rigorously verified with **180+ tests** including Property-Based Testing (PBT) via Hegel
- **Single consolidated Docker image** (distroless, multi-arch) covering both controller and proxy
- **Proxy Capabilities**: Structured logging (logr/zap), graceful shutdown with drain timeout, and CORS origin allowlist
- **Helm chart** with comprehensive proxy deployment support
